# Decision quality: can the system tell good trades from bad ones?

**Status: EXPLORATORY.** Every validation and test period here had already been examined by earlier work, so
nothing in this file can promote a strategy. Buckets, thresholds and regime cut-offs were fitted on
**development data only** and then applied unchanged to validation and test.

Figures are gross % per trade unless marked net. Brackets are 95% intervals from a stationary block
bootstrap over days (`research/intraday/decision/common.py`).

- Raw output: `research/intraday/decision/out/decision_quality.json`
- Code: `analysis.py`, plus `fixups.py` (two data-consistency corrections, explained at the end)
- Trades: generated by replaying the engine over every period. They reproduce the research test trade counts (S2 test 5,732; C1 212; C2 74).

Periods:
- S2: dev 2000–2015, validation 2016–2020, test 2021–2026.
- S1: hourly days split 40 / 20 / 40%.
- C1 and C2: dev 2020–2022, validation 2023, test 2024–2026.

Base round trips: stocks 0.08%; C1 1.06% (maker in, taker out); C2 1.32%.

## Q1. Valid setup vs ordinary noise

Matched random entries use the same day or time of day, the same holding period and the same symbol pool:
- S2: other eligible symbols' open-to-close return that day.
- S1: other symbols' 15:30–16:00 return that day.
- C1 and C2: 40 random days per trade, same coin and clock time, same holding time.

| Strategy | Dev excess over random | Validation excess | Test excess |
|---|---|---|---|
| S2 stocks+ETFs | **+0.247 [+0.188, +0.307]** (n 10,940) | +0.049 [−0.028, +0.132] | +0.013 [−0.066, +0.097] |
| S2 ETF-only | **+0.206 [+0.030, +0.381]** (n 512) | **+0.155 [+0.010, +0.301]** | +0.057 [−0.025, +0.139] |
| S1 | −0.000 [−0.027, +0.025] | −0.035 [−0.089, +0.010] | +0.027 [−0.016, +0.073] |
| C1 | +0.004 [−0.170, +0.174] | +0.221 [−0.081, +0.432] | +0.033 [−0.151, +0.226] |
| C2 | −0.113 [−0.894, +0.764] | +0.385 [−0.266, +1.124] | +0.321 [−0.435, +1.011] |

**Verdict: no, not currently.**
- **S2 stocks** separated from noise in 2000–2015, then stopped: its validation and test intervals include zero.
- **S2 ETF-only** is the only setup above noise outside development, in validation. Its test interval includes zero.
- **S1** never separates from noise.
- **C1 and C2** have intervals far too wide to separate anything (79–217 trades per period).

## Q2. Worthwhile trade vs one consumed by costs

Signal strength is gap size for S2, momentum r for S1, and σ-multiple for C1 and C2. It is split into dev
terciles. The dev mean gross in each bucket is that bucket's prediction. The gate trades only buckets whose
prediction exceeds the base round trip.

| Strategy | Spearman(strength, gross), validation | Spearman, test | Gate keeps (test) | Test net, ungated → gated |
|---|---|---|---|---|
| S2 stocks | +0.013 [−0.028, +0.060] | +0.011 [−0.019, +0.046] | 5,732 / 5,732 (every dev bucket > 0.08%) | −0.018 → −0.018 |
| S2 ETF | −0.057 [−0.176, +0.084] | +0.033 [−0.051, +0.124] | 172 / 548 | +0.046 → +0.011 (worse) |
| S1 | −0.027 [−0.102, +0.058] | +0.074 [+0.022, +0.120] | 0 / 1,440 | −0.059 → no trades |
| C1 | −0.013 [−0.345, +0.326] | +0.023 [−0.148, +0.233] | 0 / 212 | −1.024 → no trades |
| C2 | −0.093 [−0.281, +0.109] | +0.098 [−0.091, +0.239] | 0 / 74 | −0.965 → no trades |

**Calibration fails.** Dev bucket predictions don't carry over. For example, S2-ETF's strongest dev bucket
predicted +1.12% and realised −0.08% in validation and +0.09% in test. C2's weakest bucket predicted −0.96%
and realised +1.13% in test. Full tables are in the JSON.

S1's test Spearman of +0.074 is the only interval of ten that excludes zero, and S1's dev buckets showed no
ordering. One hit in ten is what chance alone produces.

**Verdict: the system cannot rank trades by expected value.**

What it can do: a cost-aware gate fitted on dev data alone **abstains entirely** from S1, C1 and C2. No dev
bucket of those strategies cleared its costs, and that matches their test outcomes.

## Q3. A position worth holding vs one whose premise has failed

Exit reasons: C1 had 262 targets, 234 stops and 3 time exits. C2 had 127 time exits and 58 stops.

| Rule | Dev | Validation | Test |
|---|---|---|---|
| C1: remove the stop, keep target and 6h limit (gross change vs actual) | **+0.397 [+0.129, +0.700]** | **+0.276 [+0.075, +0.515]** | **+0.386 [+0.238, +0.541]** |
| C1: hold to 6h, no stop or target | +0.724 [−0.284, +1.937] | +0.136 [−0.232, +0.589] | +0.036 [−0.331, +0.403] |
| C2: remove the stop (hold to 23:55) | +0.260 [−0.079, +0.619] | **+0.480 [+0.156, +0.835]** | +0.122 [−0.184, +0.412] |
| S2: exit at 10:30 if the first hour extends the gap, vs hold to close (2023-11 → 2026-10; 1,435 of 2,956 abandoned) | n/a | n/a | −0.024 [−0.079, +0.024] |

**Verdict: no.**
- C1's ±1.5σ stop consistently **destroys** value, by about 0.3–0.4% per trade in all three periods. It cuts
  rebounds that later recover.
- Even without the stop, C1's gross (about +0.42% in test) stays far below its 1.06% round trip.
- The S2 abandon rule adds nothing. Trades that extend the gap in the first hour do end badly (−1.38% held
  to close), but exiting at 10:30 locks in about the same loss.
- The system has no tested way to recognise a failed premise. Its fixed stops are worse than no stops.

## Q4. A condition it understands vs one where it should abstain

Regimes use only prior data: the trailing 20-day volatility tercile (cut-offs from dev), and the prior close
vs its 50-day average. That gives five candidate groups per strategy; "abstain" removes the group that was
worst in dev.

| Strategy | Worst dev group | Validation net: all → abstaining | Test net: all → abstaining |
|---|---|---|---|
| S2 stocks | market in uptrend (SPY above its 50-day average) | −0.017 → +0.083 [−0.132, +0.303] | −0.018 → **+0.204 [+0.044, +0.372]** |
| S2 ETF | market in uptrend | +0.064 → +0.114 [−0.170, +0.423] | +0.046 → +0.149 [−0.060, +0.346] |
| S1 | downtrend | −0.098 → −0.099 | −0.059 → −0.063 |
| C1 | lowest volatility | −0.829 → −0.893 | −1.024 → −0.835 |
| C2 | highest volatility | −0.715 → −0.715 (no validation trades in that group) | −0.965 → −0.911 |

**Verdict: no established ability. There is one exploratory lead.**
- S2 gap reversal worked better when the broad market was below its 50-day average. That holds in dev, in
  validation (interval includes zero), in test, and for ETFs too.
- It was picked from 5 groups on dev data, its validation result is not significant, and the test period had
  already been seen.
- It counts only as a hypothesis to **pre-register on data not yet examined**. It does not justify trading.
- C1 and C2 have too few trades per regime to say anything (some groups have 0–5 trades).

## Opportunity decay and the latency it implies (item 6)

| Strategy | Gross per trade by entry delay |
|---|---|
| C1, all 499 signals (5-minute resolution, hold to signal + 6h) | 0m +0.107 · 5m +0.130 · 10m +0.413 · 15m +0.361 · 30m +0.250 · 60m −0.069 (every interval about ±0.5) |
| C1, the 42 signals with 1-minute data | 0m +2.41 · 1m +2.36 · 2m +2.37 · 5m +2.14 · 10m +2.86 · 15m +2.99 (unrepresentative subset; flat) |
| C2, 185 signals | 0m +0.563 · 5m +0.604 · 15m +0.608 · 30m +0.577 · 60m +0.661 |
| S2 stocks (hourly window) | open +0.019 · 10:30 +0.012 · difference −0.007 [−0.110, +0.102] |
| S1 | Not measurable: hourly bars only, and 15:30 is the last bar of the session |

**Verdict: no measurable decay over 0–60 minutes for any strategy.** None has an edge to decay. Faster data,
decisions or order routing would buy nothing for these strategies; a 1–5 minute cycle is enough. A latency
target should only be set once a strategy shows an edge whose decay can actually be measured.

## Corrections made during this study (fixups.py)

1. **S2 hourly-window checks** first mixed daily entry and exit prices with hourly bars. BNY's hourly series is
   a different security before 2026, which produced a spurious +1.2% "10:30 entry" effect. The fix uses hourly
   prices for every leg and requires the hourly open to match the official open within 2%; 50 trades were
   dropped.
2. **C1 one-minute delays** first compared 42 cached signals against all 499. The fix compares every delay on
   the same 42.

## Summary

| Question | Can the system currently do it? |
|---|---|
| Valid setup vs noise | **No.** S2-ETF is marginal: above noise in dev and validation, not in test. |
| Worthwhile vs consumed by costs | **No ranking ability.** The dev cost gate correctly abstains from S1, C1 and C2. |
| Hold vs premise failed | **No.** C1 and C2 stops subtract value; the S2 abandon rule is neutral. |
| Understood vs abstain | **No established ability.** One exploratory lead: S2 in a market below its 50-day average. |
| Latency requirement | Minutes, not milliseconds. No edge exists to decay. |
